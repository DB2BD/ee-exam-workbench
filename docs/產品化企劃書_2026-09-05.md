# 電機工程技師工作庫產品化企劃書

日期：2026-09-05｜版本：提案 v1｜狀態：供使用者審閱，尚未授權實作或發布

## 一、產品定位與第一版目標

將現有個人工作庫整理為「找得到題、看得懂詳解、知道今天練什麼、學習進度帶得走」的電機工程技師備考工具。

首要使用者是在職、每天可投入約 20–60 分鐘的技師考生；其次是依章節補強的初學者與考前整卷練習者。這是待訪談驗證的客群假設。

第一版以技師題庫為主要入口，國考題庫作延伸練習。澳洲求職內容保留原有功能，從備考主要導覽移至獨立入口。保留純靜態與可下載使用的優勢，先完成可公開試用的產品，再決定是否收費。第一版不加入帳號、支付、雲端同步或即時 AI 解題。

核心體驗：開啟 → 繼續上次／今日複習／按章節找題 → 看原題自行作答 → 分段查看詳解 → 記錄熟悉度 → 安排下一次複習。

## 二、本次檢測依據與限制

本次為現有原始碼、建置流程及資料稽核檢查，結合前次已重現的快篩錯誤。尚未進行真人使用性測試、手機實機測速或完整無障礙稽核；以下改善建議不代表已證實每一項皆有操作故障。

| 發現 | 證據 | 對使用者的影響 |
| --- | --- | --- |
| 快篩與正式分類不同步，已確認 | `src/components/questionList.js` 以固定文字對 topic/tags/ftags 做 includes；未使用已歸位章節 | 漏題、找不到已確認的考點 |
| 跨科目殘留快篩，已重現 | 選 MOSFET 再切電機機械，仍套用原標籤而顯示 0 題 | 使用者誤認題庫沒有資料 |
| 標籤計數與結果範圍不同，已確認 | 快篩計數只限考科，列表另套用年度、難度、狀態、搜尋 | 按鈕數字與點入結果不一致 |
| 高頻統計為固定資料，已確認 | `src/components/topTopics.js` 的 STATS_DATA 寫死題數與百分比 | 題庫更新後統計可能失真；不能視為命題機率 |
| 備份互動偏技術導向，已確認 | 建置模板使用 JSON 文字區；sm2Store 匯入依序修改狀態 | 一般使用者操作負擔高；需驗證錯誤匯入是否造成部分覆寫 |
| 驗證覆蓋的分母需要解釋，已確認 | 本次 audit：256 題受稽核，239 verified、17 needs_manual_review；PE 記錄為 321 題 | 不能把 239/256 說成全題庫正確率；其餘範圍需獨立交代 |
| 首頁載入多份資料，已確認；速度未量測 | 建置模板在 head 載入 PE/GK 資料與詳解；四個抽查檔案未壓縮共約 5.44 MB，尚未含全部資產 | 首次開啟、手機記憶體與離線包體值得實測 |
| 宣傳文字與實際狀態需要統一，已確認 | 建置模板含固定 479 題初始文字及「100% 步驟推導」；CONTEXT 含 0ms／100% 離線敘述 | 容易對涵蓋範圍、驗證程度及離線能力產生誤解 |

先前 185 項測試通過，卻未攔住快篩使用情境。產品驗收必須增加「按下按鈕後真的出現正確題目」的流程測試，不能用測試數量代替使用性。

## 三、第一版改善範圍

### P0：可靠性，公開試用前完成

**P0-01 統一考點快篩與章節分類**

- 快篩以穩定章節 ID 運作，顯示名稱取自既有章節資料；沿用現有分類解析，避免再做一套分類器。
- 預設按主章節篩選；提供「包含相關考點」選項，啟用時納入次要考點，同題只計一次。全文搜尋保留為獨立工具。
- 切換考別或考科時清除考點選擇，並顯示目前作用中的條件與一鍵重設。
- 計數先套用年度、難度、學習狀態、搜尋及快捷條件，再逐章節計算；計數與點入結果共用同一個題目集合。
- GK 無可確認章節時明示未分類，不藉用 PE 題號或憑文字強行指定。

驗收：EE-112-02-1 能以 BJT 主章節找到；MOSFET → 電機機械切換無殘留；每個可點擊考點的計數等於點入結果；含次要考點時不重複；PE/GK 都有流程測試。

**P0-02 題解可信度與可追溯更正**

- 清楚區分「我的學習狀態」與「題解校驗狀態」。主畫面用繁體中文描述，不展示內部狀態代碼。
- 題解顯示來源、校驗範圍及必要假設；需人工確認者保留可閱讀內容，附具體尚缺條件。
- 增加「回報本題問題」入口，帶入 QID、版本及問題類型。第一版可先產生可複製回報內容；外部送出方式由 Sol 選擇可維運方案，讓使用者明確提交。
- 統一總題數、受稽核數與校驗數；說明不同分母，不宣稱全庫百分之百正確。

驗收：分類完成不會升級詳解；已知 17 題的限制能從詳解直接找到；每筆回報可定位同一版本單題。

**P0-03 真實統計與入口一致性**

- 高頻排行由題庫及主章節計算，顯示考別、年度範圍與分母。
- 區分「題數占比」與「有出題年度占比」，不標成未來命中率。
- 排行點入的 QID 集合，必須與統計集合相同；七層訓練入口的範圍數字也納入相同檢查。

驗收：用可手算的小型題庫驗證統計；資料更新後無須手改數字；空範圍顯示無資料。

**P0-04 安全備份與還原**

- 提供下載備份檔、選檔還原；貼上 JSON 保留為進階操作。
- 還原前驗證結構、版本、考別、QID 與狀態值，顯示預覽及合併／取代範圍；完整驗證後才寫入。
- 備份明確涵蓋 PE/GK 的進度、收藏、複習排程與提取狀態，避免只匯出目前考別。
- 顯示「儲存在此瀏覽器」與最近備份時間；寫入失敗須有可操作提示。

驗收：跨考別往返還原結果一致；損壞 JSON、未知版本或不合法狀態不改變原資料；使用者可在還原前保留原始備份。

### P1：完整備考體驗，小規模試用階段完成

**P1-01 今日開始與繼續上次**：首頁主操作收斂為繼續上次、今日複習、按章節找題。首次使用可略過設定，預設提供短練習；結束顯示完成題數與下一步。尚無學習資料時呈現清楚的開始入口。

**P1-02 行動閱讀與無障礙**：手機採原題／詳解切換，桌面保留雙欄；放大題圖、公式局部橫向捲動、關閉詳解後回到原題位置。驗收 360、390、768、1280 像素寬度；頁面無整體橫向溢出，重要按鈕建議至少 44×44 CSS 像素，鍵盤可操作、焦點可見、彈窗關閉後焦點返回觸發點。此項先實測再修正。

**P1-03 搜尋與導覽**：支援 QID、年度與既有同義詞；顯示目前篩選條件；空結果提供清除考點或重設全部。以網址保留可分享的考別、章節、題號；避免把個人學習資料放入網址。

**P1-04 載入與離線**：先量測首次進站、開題與換科速度，記錄裝置、網路及快取條件。若需拆包，保留完整下載版，另評估網頁版按需載入。分別驗證「完整下載後斷網開啟」及「網頁再次離線開啟」；產品只承諾實際支援的模式。

## 四、先不做的擴張與消融原則

第一版不以更換框架、建立後端或新增 AI 聊天室作為產品化前提。先整合既有搜尋、分類、統計入口，將重複或無實際使用者需求的畫面移出主要導覽。

沿用目前資料與編譯流程。任何新抽象都須能指出至少兩個實際使用處；有替代方案時，先比較最小直接修改。不能為簡化介面刪除題目來源、歷史學習紀錄或題解限制。

## 五、試用與成功指標

招募 5 位目標考生進行 20–30 分鐘任務測試，兼顧手機與桌面。此規模用來找阻礙，不足以證明市場需求。

| 任務 | 建議驗收目標（不是目前成績） |
| --- | --- |
| 找到指定年度／章節的一題 | 至少 4/5 人在 60 秒內完成，不需口頭提示 |
| 完成一次作答、看詳解及排程 | 至少 4/5 人獨立完成 |
| 分辨自己的熟悉度與題解可信度 | 5/5 人可正確說明差異 |
| 匯出並在另一瀏覽器還原 | 至少 4/5 人完成，測試資料零遺失 |
| 快篩與統計 | 自動驗收案例零漏收、零誤收、計數一致 |

初期採主持人觀察及自願回饋，無須先加入追蹤 SDK。若要量測七日回訪與練習完成率，先定義事件與告知方式；目標於試用基線建立後設定，不以合格率作短期產品指標。

## 六、交給 Sol 與 Luna 的執行安排

本文件先由使用者審閱；使用者轉交後才啟動。Sol 決定每個任務的審查強度，Luna 負責有界的實作，Sol 獨立驗收。

| 階段 | 工作順序 | 交付物／通關條件 |
| --- | --- | --- |
| 0：Sol 整理 | 確認範圍、分類語意、版本基線、既有修改 | 任務包、流程驗收案例、風險與估時 |
| 1：Luna → Sol | P0-01 快篩；完成後再做 P0-03 統計 | 每項獨立 diff、重現前後結果、來源與生成檔一致 |
| 2：Luna → Sol | P0-02 題解可信度、P0-04 備份 | 資料分母說明、異常還原案例、回報流程 |
| 3：Luna → Sol | P1 首頁、手機、搜尋、效能 | 實機／瀏覽器驗收紀錄、前後量測 |
| 4：使用者審閱 | 5 人試用與修正 | 試用紀錄、發布候選版本、已知限制、回復方案 |

Sol 的任務包須列：問題、預期使用者行為、涉及檔案、允許改動範圍、驗收案例、必要測試、生成檔更新方式。Luna 回報須列：修改摘要、可重現案例、測試結果及尚未解決事項。涉及分類歧義、資料遷移或兩次失敗即交回 Sol。

驗證重點是從使用者入口到結果：點快篩、切考科、開題返回、匯入失敗、刷新後進度保留。對有資料與行為風險的修改加回歸測試，避免以「字串存在」測試代替真正操作。發布候選通過全套既有測試、建置語法檢查與關鍵流程；健康分數僅作參考，不能取代內容稽核。

工作量粗估：P0 約 5–9 人日、P1 約 5–8 人日、試用與修正約 3–5 人日；係規劃量級，非承諾工期或模型執行時數。Sol 完成階段 0 後重新估算，不安排多個代理同時寫同一份生成檔。

## 七、產品化與商業化的分界

此計畫的第一個成果是「可放心試用、可維運的備考產品」。收費方案待訪談驗證付費意願、維護成本及內容差異化後另提。

公開提供或商業銷售前，需建立官方題目、第三方詳解、圖像、字型及程式依賴的來源／授權清單，確認可提供的使用範圍；本次未作法律查核，不據此推定商用授權。另確認最新年度涵蓋、聯絡回報方式、更新頻率及更正責任人。

每次發布保留版本號、變更紀錄與可回復版本；個人學習資料遷移須可預覽、備份及失敗保護。先以小規模試用修正可靠性，之後再評估擴充年度與進階服務。
