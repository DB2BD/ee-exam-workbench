## 1. 判斷與優先順序

目前靜態前端、PE／GK 分開編譯、QuestionRecord 命名檢視及可重現建置方向可以保留。沒有證據需要換框架、加後端或把整個專案重寫。

已發現的結構問題集中在：自評操作分散寫入多份狀態、UI 同時負責學習規則與導覽、讀寫狀態與實際閱讀區未接通，以及品質閘門未完整阻止錯誤。它們會造成「按鈕能按、測試通過，但紀錄或學習效果不符合介面承諾」。

| B | P1 已證實錯誤／架構 | 自評只計一次；寫入失敗不冒充完成 | 無 |

## 3. 派工規則與共同契約

Sol 先讀根目錄 `AGENTS.md`、`CONTEXT.md`、`AGENT-CODE.md`，以及 ADR-0001、0002、0006。舊 `docs/HANDOFF_第二階段使用者優化_Sol主導_Luna執行.md` 作歷史背景；本文件採用目前已發布行為作基線。

- Sol 每批自行判斷推理強度、核准檔案範圍並定義失敗探針。Luna：B/C/D/E 用 high；A/F/H 例行部分可 medium，跨狀態或瀏覽器操作改用 high。
- 同檔案寫入串行。A/B/C/D/E 都碰 `solutionModal.js`，不可同時派多個寫入者。H 腳本與 F 資料接線可獨立進行，生成 `index.html` 最後由單一整合者重建。
- Luna 每批交付來源差異、失敗前／修正後證據、測試命令、結果、未測項。Sol 不採信「全測試通過」作唯一證明，要獨立重現本批反例。
- 涉及 localStorage 的測試使用隔離 fixture；保留使用者的真實進度、收藏、備份與原始題解。
- 新邏輯使用 QuestionRecord、穩定 QID 與既有章節映射；保留 PE／GK bundle 隔離。
- 保留「每日隨機練習不自動寫入 SM2」「browse 純查看不完成每日」「四段蓋牌」「7 天近期避重」等既有決策。新增排程只能由清楚標示的使用者動作觸發。
- Luna 兩次失敗、遇到矛盾、缺失依賴或無法驗證時，交回 Sol 修正方案；不把整批標完成。若模型不可用，回報實際模型，不假稱代替模型為 Luna／Sol。

### 建議收斂的介面，而非全面換架構

將「接受一次作答自評」集中在一個有實質行為的 module。暫定 interface：

```text
submitAttempt({ attemptId, qid, examFamily, sourceMode,
                recallEntry, revealStep, selfAssessment }, dependencies)
  -> { ok, duplicate, error, nextState, nextAction }
```

這是給 Sol 確認的設計草案，名稱可調整。它須擁有題號／入口驗證、重複提交、寫入結果、該更新哪些學習狀態的規則。DOM 只收集意圖與顯示結果，不再依序呼叫多個 store 偷渡成功。避免額外建立通用事件匯流排、每個 store 一層 pass-through wrapper 或為此遷移全部資料庫。

## 4. Luna 執行卡

### A｜蓋牌答案隔離

**可改**：`src/components/solutionModal.js`、`tests/test_phase2_reliability.py`；必要時相關 CSS。**禁止**：改動雙解數值、刪除出題疑義與來源證據。

把含推導值、答案、解題建議的 scenario matrix 與其他答案性區塊移到第④段中。第④段前可保留「參考書核對／有疑義／來源連結」等不透露答案的摘要。逐一查看 `renderSolutionReviewCard` 的內容，不能只搬矩陣後就宣告無洩漏。

**Sol 驗收**：`EE-111-02-3`、另一個有 matrix 的實際題號、普通 PE 與 GK 題，初始與①②③的可見內容／無障礙樹均無完整答案值，第④段後才出現；browse 仍可直接查看但不能記每日完成。以真實 DOM 可見性判斷，不以答案字串「不存在於 HTML」作判斷，因答案可合法預渲染在 hidden 容器。

### B｜一次自評的一致性與提交保護

**必改範圍**：`src/state/attemptStore.js`（新增）、`src/components/solutionModal.js`、`src/components/dailyPractice.js`、`src/state/practiceStore.js`、`src/state/recallStore.js`、`src/state/sm2Store.js`、`src/state/store.js`、`scripts/build_workbench.py`、`tests/test_attempt_store.py`、`tests/test_phase2_reliability.py`、`tests/test_sm2_spaced_repetition.py`、`tests/test_recall_store.py`、`tests/test_daily_practice.py`、`tests/test_backup_restore.py`。

Sol 已核准單一深層提交介面 `submitLearningAttempt(...)`：它擁有驗證、短期冪等、純計算、多 key 寫入、recovery journal、best-effort rollback 與成功後記憶體同步。journal 是暫態恢復資料，不加入一般備份 schema。其他檔案先退回 Sol 說明必要性。

1. 先在隔離測試覆現 B1/B2/B3，再實作共享提交操作；每次作答以穩定 attemptId 識別。連按／重入不另算作答；明確開始新作答才產生新 ID。失敗可安全重試。
2. 先驗證 QID、考別、模式、揭露資格與輸入評分，再計算下一份狀態；寫入確認成功後才更新記憶體、完成 UI 或前進。
3. 沿用現有 keys 的方案須明列多 key 寫入、失敗回復與重試策略。localStorage 多次 setItem 不是原子交易；可重用備份匯入的 snapshot／回復思路，但不得把 best-effort rollback 宣稱為斷電安全。若回復也失敗，保留可恢復資訊、明示未完成並阻止再次累計，交回 Sol 判定；不要靜默重設進度。
4. 保存失敗回傳明確結果；移除吞例外後宣告成功的路徑。取消或綁定 rating 5 的延遲換題 callback，關閉／改開其他題後不能讓舊 callback 操作新題。
5. 考別取自正在作答的 QuestionRecord，不能由背景目前頁籤決定寫入位置。Sol 先重現跨考別開題測試，再判定是否需修復路由。

**Sol 驗收**：daily、due-review、一般 browse 自評分別測 1/3/5；同 attemptId 兩次提交只記一次；每一個相關 key 輪流拋 quota，確認無假成功／假前進，正常重試僅一次；QID 不符、daily browse、未達第④段全部拒絕。測試「rating 5 後立刻關閉並開另一題」不被舊計時器換題。驗證 PE／GK 的 progress keys 無交叉污染。新增持久欄位必須涵蓋備份／舊資料相容，記錄其 schema 版本。

**退出條件**：B1/B2/B3 三個反例全部由紅轉綠。任一 key 回復失敗情境仍無法安全重試，則退回 Sol，不進 C／D。

### C｜揭露進度與提取能力分開

**可改**：`src/state/recallStore.js`、`solutionModal.js`、必要的 B module、`reviewPage.js`、`tests/test_recall_store.py` 與對應 UI tests。若契約語意改變，同步 ADR-0006／CONTEXT 對應段落。

1. `revealStep` 只代表看過第幾段；`selfAssessment` 代表本次自評。看過第④段不自動推定會完成推導。
2. 修正升級：每升一級把該級 streak 歸零，失敗只退一級；用不同 attemptId 驗證。全成功、從 L1 開始的 level 應為 `[1,2,2,3,3,4]`。
3. 評分 3 不能因 revealStep=4 就變成 achievedLevel=4。Sol 在派工前核定精簡量尺：建議 1=無法完成、3=需要提示、5=揭露前能獨立完成；提示型成果不應滿足獨立推導層級。若要逐段評估能力，使用者在各段自行回想後回報，不用揭露次數推算。
4. 蓋牌順序保留。第④段自評文案說明應回顧「揭露前」的作答狀況，不宣稱系統自動批改。
5. 舊 level 保留並標示為既有紀錄；不得憑空回算歷史能力。若舊 streak 缺少分層證據，保守歸零並在遷移說明中列出。

**Sol 驗收**：六次獨立成功才從 L1 升至 L4；高級失敗只降一級；重複提交不升級；看完全部但自評3不能冒充獨立推導。普通開題不新增 attempts。舊備份匯入沒有新增成功／重新完成題目。

### D｜到期複習與日期可信

**可改**：`sm2Store.js`、`solutionModal.js`、`reviewPage.js`、對應 SM2／reliability tests；必要的 session 持久化與 backup schema 由 Sol 一次指定。

1. 以一致的本地日曆日計算「今日／明日／到期」，提議預設使用瀏覽器時區，至少測 Asia/Taipei；7 天避重繼續使用經過時間戳，兩者不可混用。保留舊日期字串，不對全部歷史排程盲目加減一天。
2. 每次評分顯示實際演算法算出的下次日期；daily 顯示「本題已自評、未加入到期排程」。移除固定「3 天後」與前端 EF 技術詞。
3. 到期 session 明確記錄已評分、略過、尚未處理。略過不改 SM2，保留到期資格；完成摘要只依成功提交計數。建議成功評分後三種評分均採一致的下一題操作，不只 rating 5 自動前進。
4. `advanceReviewSessionItem` 在 reviewPage 與 solutionModal 各有同名定義，經 build 順序後由後者覆蓋。收斂為單一擁有者，入口共用同一份 queue/index/結果，避免未來改了無效函式。

**Sol 驗收**：台北 23:59→00:01、月底／年底、重新整理，今日到期一致；首次 rating3 的顯示與實際 interval=1 一致；1評分+1略過數字正確。新增明確略過／結束操作後，再驗證兩題全略過摘要=0已評分/2略過且仍到期；此為修正後案例，現行最後一題沒有下一題按鈕，不能當成修正前已證實路徑。離開頁面後舊回呼無效；只有一個正式佇列前進實作。

### E｜共用閱讀體驗與真正續做

**可改**：`dailyPractice.js`、`solutionModal.js`、`practiceStore.js`、必要的 backup 部分、`src/styles/{components,modal}.css`、build shell 與瀏覽器測試。

1. 直接保存實際左右閱讀 pane 的 scroll、手機正在看原題或詳解、modal 是否正在本輪作答、revealStep、必要的小題位置；逐題綁定 QID。把舊外層 scroll 遷移為保守預設，不宣稱已知舊詳解位置。
2. 讀取還原需等待內容及圖片／公式尺寸穩定；儲存採適度節流，離開／關閉／pagehide flush。失敗應可見，不能每個 scroll event 都假成功。
3. 手機預設原題／詳解切換，同時只顯示一個主要閱讀面；桌面保留雙欄。四段引擎共用，模式用「今日練習／到期複習／查看詳解」標籤區分。
4. 開 modal 記住實際觸發按鈕、移入焦點並管理 Tab 範圍；關閉回到可用觸發點。保留已修好的題圖 trigger 與 Escape 分層關閉；文字輸入欄位中的方向鍵不觸發跨題。

**Sol 驗收**：每日題A第③段、原題scroll120／詳解scroll640，刷新後續做恢復同題同段，modal 確實呈現該位置；切題B從自己的位置開始。360/390/768/1280 CSS寬度、亮暗色皆測，整頁無橫向溢出、公式局部捲動、主要按鈕至少44×44。慢圖片載入後位置不跳回頂端；鍵盤Tab不穿透背景、關閉回焦，燈箱Escape不關底層詳解。

### F｜把題型多樣性接到正式抽題流程

**可改**：`dailyPractice.js`、必要的 `practiceStore.js`、`tests/test_daily_practice.py`、`tests/test_phase2_daily_ui.py`。先沿用 taxonomy／formulaTags，只有證據不足時列出缺資料，不批次猜測章節。

chapter 回傳主章節穩定 ID；type 回傳獨立且可追溯的題型資訊，不能再次回傳章節名稱。formulaTags 是候選依據，不直接把任何公式字串當可靠題型。Sol 檢查至少兩個章節的實際題目與 tags，指定可用映射；缺值回傳 unknown，不當成額外多樣性。

**Sol 驗收**：以正式 `dailyPracticeStart → dailyPracticeFacet → createDailyPracticeQueue` 路徑，建立同章節兩個已知題型各多題的 fixture；候選充足時一輪包含兩個題型。再驗跨章節優先、7天邊界、候選不足按最久完成補入、同輪QID唯一、刷新不重抽、固定隨機來源可重現。分別報「演算法測試」與「正式接線測試」，不能只傳 stub chapterOf/typeOf。

### G｜讓考生知道下一步、減少無效點擊

本批是產品建議，使用者接受本提案後實作；不是現有 ADR 的 bug。

**可改**：`dailyPractice.js`、`reviewPage.js`、`topTopics.js`、`header.js`、必要的 build shell／CSS 與 UI tests。新增儲存欄位須接入 B 的提交與 backup 契約。

1. 今日練習原題頁提供一個直接「開始蓋牌」入口，開啟相同閱讀器，不必先去詳解頁再按一次。純查看保留次要入口。
2. 修正頂部仍寫「點此全開」但實際被禁止的提示；四段只突出目前可按的下一段，禁用未到達步驟並顯示原因。
3. 自評摘要列「本輪已完成、需要提示／無法完成的題目、錯誤原因、下一步」。daily rating1仍依既有決策不自動SM2，可提供明確「加入到期複習」動作；點擊後才建立排程並顯示日期，既有更早到期日不被推遲。同一動作重按不反覆累加複習次數。
4. 錯誤原因沿用已存在的分類，提供對應錯題清單入口；不再做另一套自動分類器或未經驗證的AI診斷。
5. 統計區分「本輪自評完成」「自訂掌握標記」「提取能力L1–L4」「到期題數」。七層訓練說明為七種訓練路徑，不與L1–L4混為升級階梯。不從手動標記推論真實留存率。
6. 用「電路學・民國114年・第1題」作主要題目標籤，QID 保留為可複製次要識別。未排程空狀態與「今天沒有到期」分開。

**Sol 驗收**：原題頁一個主要操作即可進蓋牌；自評後能看清楚哪些題需再練。daily忘記但未加入排程時，不能顯示已安排明日；點「加入」後才在同考別到期清單查得到。fixture `progress=1,recall=L1,nextReview=明日` 的標籤明確且不暗示都已穩定。各工具仍可從更多工具到達。

### H｜發布閘門、文件與效能基線

**可改**：`scripts/verify_slicing_and_links.py`、`.github/workflows/deploy-pages.yml`、quality gate tests、`README.md`、既有 handoff 狀態說明、發版紀錄／使用說明。ADR 或 AGENTS 修改時依相應技能與專案規則閱讀後再動。

1. 所有切片、missing/duplicate/extra canonical、無效crop、本地PDF錯誤都彙總且退出非零；MC 只豁免其題解分段策略，仍檢查其來源／資產。成功條件包含全部計數。
2. 隔離fixture故意破壞每一種資料，assert subprocess exit code !=0。再把此檢查明確接入 artifact upload 之前。保留網路離線測試可重現；外部URL只檢查格式時標「未驗連通」，不要冒充HTTP200。遠端連通檢查若新增，與離線核心閘門分開。
3. 修正文檔：實際 build 是 src CSS/JS 編入 index、四個資料bundle與libs/assets以相對檔案引用；只下載index不構成完整離線包。移除0ms承諾，列出完整資料夾下載、外部PDF限制與版本識別。舊handoff標記歷史基線與新文件連結，不能保留為看似尚待開始的唯一現況。
4. 檢查 Pages 整庫 artifact 的必要性，提出有明確資產清單的 staging 方案；先列保留範圍（四bundle、libs/fonts、原題圖/PDF、所需相對連結等），驗全部本地引用再縮減。不能只保留index造成離線或圖片失效。
5. 量測載入到「可開始練習」、首次開題與切題耗時、主執行緒長任務、傳輸量，區分冷／暖快取與手機模擬。基線四資料檔合計約5MB（未壓縮）；這只是規模，不是已證實效能瓶頸。只有量測顯示問題才安排另一批延遲載入，維持file://相容，不先導入ESM fetch或service worker。

**Sol 驗收**：壞fixture退出非零、CI在upload前停止；正常資料通過。完整離線資料夾斷網仍可查題／本地圖／既有詳解；外部不可用明確提示。發版頁能辨識當前commit，README、使用說明與已驗證功能一致；提供artifact資產清單與效能量測方法，不只報健康分數。

Sol 逐批審查後才整合，對新基線重建並執行：

```bash

python3 scripts/run_all_tests.py
python3 scripts/check_html_js_syntax.py
python3 scripts/verify_slicing_and_links.py

```

`review-candidate` 用於可重現的本機驗收；正式發布沿用 CI 的 commit 識別。只有改資料來源時才執行對應 PE/GK 編譯器；純前端改動不重寫稽核狀態。

真實瀏覽器使用隔離使用者資料的本地HTTP預覽，避免file://工具限制導致整批視覺驗收略過；另以支援的瀏覽器驗證完整file://離線包。工具不能驗證的情境如實列為未測，不能用Node假DOM代替CSS布局證據。

最終端到端清單：

- 首次進站→選科→3題→原題圖→四段→1/3/5自評→摘要→再練。
- 自評連點、每個寫入點失敗與安全重試、關閉後舊callback無效。
- 中斷→刷新→續做，題號／佇列／modal／段落／實際雙側位置一致。
- 到期複習→評分／略過→摘要與剩餘到期數一致；跨午夜不錯日。
- 同章節不同題型、跨章節、候選不足、近期避重、PE/GK隔離。
- 含雙解矩陣題的①②③無答案洩漏，第④段保留全部分支與出題疑義。
- 360/390/768/1280寬度、亮暗色、鍵盤、圖像錯誤、公式、焦點恢復、更多工具。
- 舊備份匯入、無效備份拒絕且不部分覆寫、新欄位往返一致。

交付文件包含：每批ID／commit或差異、已驗證／未測／待使用者判定表、重現命令與結果、手機模擬與桌面畫面、備份遷移說明、試用入口及回復方式。真人手機結果與瀏覽器尺寸模擬分開標示。已知待人工核對題解保持原狀，不為提升健康分數消除旗標。

## 6. 延後處理與學習依據

目前不建議加入帳號／雲同步、換框架、FSRS替換、全題庫新分類器、AI自動批改或更多排行榜。也不把 QuestionRecord／PE-GK隔離移除當成「消融」。評估任何新增module時，應說明它取代了哪些重複責任；沒有可量測用途的包裝不增加。

間隔與交錯練習、作答後可採取行動的回饋有研究支持，但不能由此推定本產品的四次按鈕揭露、七層命名、固定7天或3題是最佳教學參數。上述產品設計是針對本工作庫的建議，效果需以使用者試用與後續回想表現驗證。

- [MIT Open Learning：Spaced and interleaved practice](https://openlearning.mit.edu/mit-faculty/research-based-learning-findings/spaced-and-interleaved-practice)
- [Retrieval Practice：Metacognition and Feedback](https://www.retrievalpractice.org/feedback)

試用先量測「成功續做率、同題重複計次數、同輪已知題型覆蓋、從原題到開始蓋牌的操作數、延後再次作答的自評表現」。不引入追蹤SDK；由本機紀錄／人工驗收提供資料，清楚標示樣本不足與自評限制。
