# 發版紀錄 v1.3.10

日期：2026-10-13

主題：自動快照與一鍵還原。瀏覽器資料遺失時不再只能靠手動匯出的備份檔；App 會在瀏覽器內自動留快照，備份視窗可直接還原。

## 這版改了什麼

- **自動快照**（新檔 `src/state/snapshotStore.js`）：內容就是「下載備份」同格式、同 schema 2.1.0 的完整資料，外加 `{ id, takenAt, day, reason, counts }`。
  - 儲存：IndexedDB（DB `ee-exam-snapshots`、store `snapshots`）；IndexedDB 不可用或出錯時退回 localStorage 鍵 `EE_EXAM_SNAPSHOTS_V1`，最多 2 份。所有存取都包 try/catch，失敗靜默略過、不影響其他功能。
  - 不放進備份檔、不改 `USER_BACKUP_VERSION`。
  - 保留規則（純函式 `snapshotRetain`）：每個本地日期最多一份「每日」（同日取最新），保留最近 7 個日期；「匯入前」「還原前」合計保留最新 3 份；另外永遠保留「結果卡＋已完成」最多的那一份（同分取較新），資料遺失超過一週才發現也救得回來。
- **觸發**：
  - 每日：App 啟動後若今天還沒有每日快照就拍一份（非同步、不阻塞畫面）；結果卡、已完成、SM-2 全為 0 時不拍。
  - 匯入前：`applyImportedBackupJSON` 寫入前先讀下目前資料，匯入成功後存成「匯入前」。
  - 還原前：還原快照前先拍「還原前」。
- **備份視窗新增「自動快照」區**：每列「日期 時間｜種類（每日／匯入前／還原前）｜結果卡 N 筆・已完成 M 項｜還原」，最新在上，無快照時顯示「尚無快照」。「還原」為兩段式（第一次變「再按一次確認還原」，3 秒自動復原）；還原走取代模式的既有驗證，成功後重新載入頁面，失敗則顯示既有錯誤區塊。
- **順帶修正**：
  - 匯入成功後，若成績分頁正顯示中會立即重畫（先前要切走再切回才更新）。
  - 監聽 `storage` 事件：另一個分頁改了今日任務／回想／SM-2／做題進度與星號後，本分頁重新載入記憶體狀態並重畫今日任務卡，避免舊分頁用記憶體中的舊資料蓋掉新資料。
  - 啟動時呼叫一次 `navigator.storage.persist()`（無任何文字、結果忽略）。

## 這版沒改什麼

- 備份檔格式與 schema、既有匯入／匯出行為、`pacing.js`、今日任務流程、其他畫面文案。
- 不加雲端、不加伺服器。

## 實作備註（與規格的差異）

- `buildUserBackupSnapshot(options)` 新增選項 `skipMetadata`：自動快照讀同一份資料，但不寫入「最近備份時間」，否則快照會讓「下載備份」提醒被誤判為已備份。不帶選項時行為與先前完全相同。
- 「匯入前」快照在寫入前即讀取資料，但匯入驗證失敗時不儲存，避免無效匯入擠掉有用的快照。
- localStorage 退路另設單份大小上限（約 120 萬字元），超過則略過，避免兩份快照占滿約 5 MB 配額而讓 App 自己的儲存失敗。
- 快照找不到或資料損毀時，還原錯誤沿用既有字串「匯入失敗：JSON 格式無效，未修改任何資料。」，不新增文案。

## 風險與已知限制

- 快照與 App 資料在同一個瀏覽器設定檔：清除網站資料或換瀏覽器時快照一起消失，仍需偶爾「下載備份」；`persist()` 只降低被瀏覽器自動清掉的機率，不是保證。
- 每日快照拍的是當天啟動時的狀態；啟動前就已遺失的資料靠「紀錄最多那份永遠保留」救回。
- 無痕視窗或 IndexedDB 被封鎖時退回 localStorage（最多 2 份），保留的天數較少。
