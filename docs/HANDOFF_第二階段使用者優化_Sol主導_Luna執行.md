# 第二階段使用者優化交接書

狀態：待使用者審閱；需求方向已確認，本文件尚未授權派工、實作或發布。

接手者：Sol 主導、Luna 執行。工作庫：`/Users/a/技師考試/歷屆試題_104-114年`。

參考基線：`v1.0.5`／`65c9b18`。接手時重新核對 HEAD、工作區與遠端，保留後續變更。既有紀錄為 215 項測試通過，並非第二階段已驗收。

## 1. 任務目標與啟動界線

讓首次使用的在職考生，可以在手機上開始短練習、讀懂原題與詳解、接續中斷的練習，且每日抽題有足夠多樣性。

使用者審閱本文件並下達啟動指令後，Sol 才拆分任務與派給 Luna。最終交付可試用版本與驗收結果，待使用者試用確認後才推送或發布。先前 v1.0.5 的發布授權不視為本階段的發布授權。

## 2. 已確認的產品決策

| 項目 | 核定行為 |
| --- | --- |
| 首頁 | 三個主要入口：開始練習、繼續上次、找題。知識圖譜、七層訓練、統計、速查收進更多工具，功能仍可到達。 |
| 短練習 | 每輪預設 3 題，先選考科即可開始；完成後提供再練 3 題與本輪完成摘要，不承諾固定作答分鐘數。 |
| 隨機範圍 | 預設限選定考科，另提供跨科混合；跨科不代表自動混入另一考別，維持既有 PE／GK 邊界。 |
| 題型多樣性 | 同一輪盡量分散章節與題型，避免同類計算連續出現。 |
| 近期避重 | 優先避開最近 7 天已完成題目；僅打開或查看詳解不算完成。候選不足時由最久以前完成的題目補入。 |
| 複習入口 | 隨機練習與到期複習分開，到期複習依記憶排程保留必要重複；在首頁與練習入口仍須容易找到。 |
| 續做 | 恢復上次題目、練習佇列與詳解揭示進度。一般練習中斷不計時。 |
| 手機閱讀 | 頂部固定原題／詳解切換，各自保留捲動位置；底部上一題／下一題。首次進題顯示原題，選擇看詳解才揭示。 |
| 桌面閱讀 | 保留原題與詳解雙欄對照。 |
| 模考 | 依真實經過時間倒數，支援重新整理後恢復；使用者主動暫停的既有語意由 Sol 核對並保留。 |
| 發布條件 | 功能與關鍵流程驗收完成後，先交使用者試用，再發布。 |

## 3. Sol／Luna 分工

**Sol**：確認基線、重現問題、決定最小可行設計與任務順序、界定每批修改檔案、獨立驗收及整合。每批自行判斷需要的推理強度，不預先固定。負責最終使用者流程、資料相容性與生成檔一致性。

**Luna**：依有界任務實作、執行針對性測試並交付差異與重現步驟。例行低風險工作用 medium；涉及狀態、抽題判斷或複雜介面用 high。模型實際不可用時交由 Sol 決定替代並如實回報，不假稱已切換。

Luna 連續兩次失敗、遇到未預期流程、資料矛盾、缺少關鍵資訊、無法判斷下一步或完成後無法驗證時，交回 Sol。Sol 可修正策略後交還 Luna，也可直接完成或提出需使用者決定的問題。

同一批不要讓多個 Agent 同時寫同一檔案；生成檔由 Sol 安排單一整合者重建。

## 4. 執行順序與完成條件

### A. 基線與可靠性

先讀根目錄 `AGENTS.md`、`CONTEXT.md`、`AGENT-CODE.md` 與相關 ADR；原產品企劃 `docs/產品化企劃書_2026-09-05.md` 作背景，本交接書的已確認決策優先於舊提案。

逐項重現下列程式檢查發現，再修正。下列影響仍需操作驗證，不可直接宣稱已完成實機重現：

1. `reviewPage.js` 的到期題數按考科計算，開始複習仍可能沿用章節篩選，造成入口數字與實際佇列不一致。
2. `solutionModal.js` 的全域蓋牌模式可能在關閉後殘留，讓模考的看詳解入口仍顯示蓋牌。
3. `mockExamTimer.js` 使用 interval 每次減一秒，缺少截止時間校正與持久化。
4. `AGENT-SPEC.md` 的 PE tuple 欄位順序與 `src/domain/questionRecord.js` 不符；依程式、Python schema 與測試核對後修正文檔，不為遷就錯誤文件更動資料。

完成條件：有可重現案例與修正後結果；到期數字、佇列、完成提示使用同一範圍；不同開題入口模式正確；模考背景延遲與重新整理能恢復正確剩餘時間。

### B. 多樣性抽題與練習紀錄

沿用現有章節／題型映射，先檢查可用分類品質。避免另外建立一套未驗證分類器。Sol 決定具體權重、種子與儲存結構，記錄理由；不要求使用者指定演算法。

抽題規則：

- 每輪 QID 唯一；候選足夠時抽滿 3 題。同樣條件下應有不同可行組合，不能固定取排序最前面三題。
- 先在考別／考科範圍內優先選未完成或超過 7 天未完成的題目，再盡量分散題型；不為湊不同題型提早重抽近期完成題。
- 優先覆蓋不同主章節；章節相同時再用可追溯的題型資訊分散。無題型資訊時如實退回章節層級，不把未知分類當成已證實不同題型。
- 不足 3 題才放寬近期避重，由最久以前完成者補入；整個範圍只有 1–2 題時按實際題數開始，說明原因，不在同輪重複湊數。
- 7 天以完成時間戳計算；「完成」需要明確完成動作，不以開題、看答案或按下一題推定。沿用既有熟悉度評分操作時，清楚區分練習完成紀錄與掌握程度。
- 產生後保存本輪佇列，重新整理與續做不重抽；再練一輪才重新抽選。到期複習不受 7 天隨機避重規則阻擋。

完成條件：以可控制時間與隨機來源的案例驗證跨章節分散、相同章節題型分散、7 天邊界、近期補題順序、候選不足、同輪不重複與續做不重抽。測試避免以不穩定的單次隨機結果判定成敗。

### C. 首頁與手機流程

將三個主要入口與更多工具落到現有介面，整併重複的蓋牌按鈕。到期清單為空時區分尚無練習資料與今日無到期題，不顯示無證據的「記憶已穩固」結論。

完成條件：首次使用能從選科開始短練習；一輪結束能再練或離開；所有既有工具仍可找到；360、390、768、1280 CSS 像素寬度可操作。整頁不橫向溢出，公式可局部捲動、題圖可放大；主要觸控目標至少 44×44 CSS 像素；鍵盤焦點可見、彈窗關閉後回到觸發點。

### D. 續做、模考與資料保護

新增練習紀錄與 session 必須與既有收藏、SM-2、學習狀態、備份／還原相容。Sol 明確列出新增資料的備份範圍、舊備份預設值與不可還原情況。

完成條件：刷新後恢復題目、佇列、揭示進度與手機兩側閱讀位置；模考背景／睡眠後依時間校正，到時不出現負數或重複完成事件；損壞的 session 能提示並安全重新開始；儲存失敗有提示。舊備份仍可匯入，無效匯入不部分覆寫；開啟備份不修改使用者紀錄。

### E. Sol 整合驗收與試用交付

修改來源後按實際影響重建；前端改動執行 `python3 scripts/build_workbench.py`。涉及資料來源才執行對應資料編譯器，避免無關稽核資料重寫。

完成前執行既有 `run_all_tests.py`、`check_html_js_syntax.py`、`verify_slicing_and_links.py` 與 `git diff --check`，並實際操作本階段主要流程。測試數量、健康分數不能替代使用性驗收；模擬尺寸與手機實機測試須分開標示。

完成條件：Sol 提供整合差異、流程驗收結果、失敗／未測項、手機與桌面畫面、試用方式及回復方式。使用者可試用後再決定發布。

## 5. 範圍與交付格式

主要涉及 `src/components/`、`src/state/`、`src/styles/`、`scripts/build_workbench.py`、對應測試與文件；具體檔案由 Sol 每批指定。保留 PE／GK 資料隔離、題源、題解限制與人工複核狀態。

本階段不引入帳號、付費、雲端同步、追蹤 SDK、框架替換或新的即時 AI 功能。跨裝置延續以既有手動備份／還原能力為基礎。

每批 Luna 回報：問題與修改摘要、檔案清單、重現步驟、測試結果、尚未解決事項。每批 Sol 回報：獨立驗收方法、通過／退回與理由、使用者可觀察的結果、下一批任務。

最終對使用者回報：完成項目、試用入口、已知限制、資料相容性、測試證據與待發布狀態。未獲本階段發布指令前，保持本地候選版本，不推送、不建立公開發布。
