# To Spec Skill (by Matt Pocock)

Converts messy discussions, decisions, and ideas into a clean, structured, and unambiguous **Technical Specification**.

## 🎯 Format & Structure

1. **Problem Statement & Goals**: Clear non-goals and goals.
2. **Architecture & Component Boundaries**: High level data flow and models.
3. **API & Interface Definitions**: Exact function signatures, metadata schemas, and state transitions.
4. **Edge Cases & Failure Modes**: Network, validation, performance, and boundary behavior.
5. **Verification & Acceptance Criteria**: Measurable definition of done.
