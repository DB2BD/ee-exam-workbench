## 1. 「最精確」與「無多餘內容」的可驗收定義

### 1.0 題目裁切精確（每張 PNG）

- **C1 完整**：題號、題幹、所有子題、配分、圖、表、圖說（如「圖二」）全數包含，無截斷的文字行或圖線。
- **C2 無滲入**：不含前／後一題的任何文字或圖。
- **C3 無版面雜訊**：不含試卷表頭（考試名稱、代號、等別、類科、科目、考試時間、座號）、注意事項、頁尾（代號／頁次）、「（請接背面）」「（請接第 X 頁）」。
- **C4 緊湊**：跨頁接縫與上下留白只保留固定邊界，不出現大片空白。
- **C5 可重現**：修正一律改 `scripts/crop_pe_questions.py`（規則或 `MANUAL_STARTS`／新增手動結束座標）後重跑產生，不得手改 PNG；`data/pe-question-crops.json` 由腳本輸出。


### 1.1 精確（硬性，全數通過才可保留或升級 `verified`）

- **P1 題幹一致**：所有已知數值、單位、接線、極性、方向與官方裁切圖逐項一致（必須實際開圖，不得只讀舊題解）。
- **P2 子題完整**：題目每個（一）（二）…都有對應的最終答案，且以 `\boxed{}` 標示並帶單位。
- **P3 數值獨立重算**：`verification/pe/EE-YYY-SS-N.py` 以第一原理（SymPy／NumPy）獨立求解，`assert` 每個 boxed 答案；相對誤差 ≤ 0.5%（或精確符號相等）。腳本不得讀取或複製題解中的中間結果。
- **P4 第二方法驗算**：題解中的驗算必須使用與主解**不同**的方法（回代、KCL/KVL、功率守恆、極限／終值定理、tr／det、單位檢查），不得重抄主解。
- **P5 條件誠實**：題幹真缺條件時才寫分支，並明示假設；不得為湊唯一答案捏造參數，也不得對條件完整的題目加無謂分支。
- **P6 LaTeX 可渲染**：通過 `scripts/katex_linter.py` 與新增 lint 的損毀樣式檢查。

### 1.2 無多餘內容（以 lint 量測）

- **R1 一次推導**：同一個 boxed 數值只出現一次推導；驗算段只出現「代回後等式成立」所需的最少行。
- **R2 禁止段落**：不得出現重述型段落（`完整教學推導`、`得分點拆解`、`校驗紀錄`、`審查結論`、`考題延伸`等）與正文稽核史（「升級」「原詳解」「本次修正」）。
- **R3 失分點限本題**：最多 3 條，且每條必須指涉本題的具體量（例：「本題 \(a^2=4\) 折算方向」），泛用提醒（「注意單位」）刪除。
- **R4 不重述 metadata**：正文不再寫 `source_crop` 路徑、QID、驗證日期；這些只在 frontmatter。
- **R5 長度約束**：不設硬性上限，但若新版字數 > 舊版，結果報告必須說明增加的內容屬於 P1～P5 中哪一項。

## 2B. 題目裁切修正流程（Phase 0B）

1. **腳本層一次修正**（主 session）：在 `crop_pe_questions.py` 依 PDF 文字座標辨識並排除版面雜訊區塊（表頭、注意事項、頁尾、「請接背面」）；文字層損毀的年度改用手動座標加上「結束座標」；跨頁片段若扣除雜訊後無實質內容則不拼接；紅→綠補 `tests/test_pe_question_crops.py` 回歸測試（至少涵蓋 104-電子學-Q02、108-電力系統-Q04）。
2. **全量重產 323 張**，並以像素層檢查自動篩出可疑圖：底部或頂部空白比例過高、高度異常、跨頁接縫附近有文字。
3. **逐張視覺稽核**：每科一個子 Agent 開啟每張新裁切圖與對應 PDF 整頁渲染，依 C1～C4 判定並回報 `{qid, verdict, defect, suggested_fix}`；不合格者由主 session 改腳本座標後重產，再由**另一個**子 Agent 複查，最多 3 輪。
4. 題解迭代（第 3 節）中的 Solver 若發現裁切問題，同樣回報給主 session 修腳本，不自行繞過。

## 3. 迭代迴圈（每題）

```text
Round k (k ≤ 3)
 ┌─ S｜Solver（盲解）：只看官方裁切圖，不看舊題解 → 寫 verify 腳本並跑出答案
 ├─ D｜Diff：比對 S 的答案與現行題解 → 分類 match / mismatch / 題幹疑義
 ├─ E｜Editor：依版型重寫 canonical（mismatch 時以 S 為準但需寫明差異證據）
 └─ R｜Reviewer（全新 context，盲審）：讀裁切圖＋新題解＋verify 腳本，依 1.1／1.2 逐條給 pass/fail
收斂條件：R 全數 pass，或連續兩輪 E 無實質改動
未收斂（3 輪後仍 fail）或 S 與舊答案不一致且證據不足 → 轉入人工佇列，不強行改答案
```

- S 與 R 必須是**不同的子 Agent 呼叫**（符合 `CONTEXT.md` 規則 6 的 Solver／Verifier 分離）。E 可與 S 同一個 Agent。
- `mismatch` 一律在結果報告中獨立列出「舊答案 → 新答案＋證據」，這是你最需要親自看的部分。

## 6. 狀態變更規則

- 只能由主 session 改 `audit_status`；Worker 只提出 `proposed_status`。
- 升級條件：P1～P6 全過＋Reviewer pass。`reference_book_verified` → `verified` 另需 verify 腳本與參考書答案一致或差異已說明；有衝突則維持原狀態。

- `solution_hash` 由 `python3 scripts/audit_pe_solutions.py --write` 重算，不手改。

## 8. 自動執行的停止條件（只有這些情況會回頭問你）

1. Phase 1 試點完成（一次性確認版型）。
1b. 題目裁切與題解舊有題幹抄錄不一致，且影響答案時（併入第 2 點的清單）。
2. 某題 Solver 結果與舊答案**及**參考書都不同，且 Reviewer 支持新答案——即「我們認為原答案錯了」的情況，彙整成清單一次問。
3. 需要修改測試斷言才能精簡的題目（彙整後一次問）。
4. 任何 push、發版、或刪除人工佇列項目。
